# ESL Scanner (Android)

Приложение сканирует штрих-код товара и штрих-код/QR ценника (ESL), пишет пару
в промежуточную таблицу в Oracle и запускает процедуру выгрузки в ESL_WORK.
Подключение к Oracle — напрямую, по JDBC (thin driver), без промежуточного сервиса.

## Как открыть и собрать

1. Открой папку `EslScanner` в Android Studio (Giraffe/Koala или новее).
2. Дай Studio синхронизировать Gradle (гугл-репозиторий и Maven Central должны
   быть доступны — ojdbc8 и ML Kit подтягиваются оттуда автоматически).
3. Собери APK: `Build > Build Bundle(s) / APK(s) > Build APK(s)`, либо
   `./gradlew assembleDebug` из терминала (после первого открытия в Studio,
   когда появится gradlew).

## Схема данных (подтверждено)

Таблица **UNIMARKET.YLIN_EPRICE_GOODS**: составной ключ `MAG_COD + COD`,
плюс `ESL_BARCODE`, `UPDATETIME`, `ESL_SIZE`, `UPDATE_STATUS`, `STATUS`,
`LAST_CHECK_TIME`, `LAST_ONLINE_TIME`. Так как строка на пару
"магазин+товар" уже существует, приложение делает **UPDATE**, а не INSERT:
проставляет `ESL_BARCODE`, `UPDATETIME = SYSDATE` и `STATUS` в значение,
которое подхватывает существующий процесс выгрузки.

## Что ещё нужно уточнить/поправить

- **Справочник "штрих-код товара → COD"**: пока неизвестен, поэтому в
  настройках есть три поля (таблица / колонка штрих-кода / колонка COD) —
  если оставить их пустыми, приложение считает, что отсканированный код
  товара — это уже сам COD. Как только узнаешь реальную таблицу, впиши её
  в настройках (без пересборки APK) — поиск COD включится автоматически
  (`OracleClient.resolveCod()`).
- **Значение STATUS для подхвата выгрузкой**: по умолчанию `'NEW'` —
  не подтверждено, нужно посмотреть, что реально ожидает
  `prismart_api_send_new`/`prismart_api2_new` (или тот процесс, что читает
  `STATUS`/`UPDATE_STATUS`). Меняется в настройках.
- **Сигнатура процедуры выгрузки**: по умолчанию
  `PRISMART_API_SEND_NEW.PUSH_TO_ESL_WORK(mag_cod, cod, esl_barcode)` —
  правится в `OracleClient.callUploadProcedure()`, если реальная сигнатура
  другая, или имя процедуры меняется в настройках без пересборки.

## Как это работает

1. Экран `MainActivity`: кнопка "Сканировать товар" → камера (ML Kit,
   офлайн-распознавание любых форматов штрих-кодов) → код товара.
2. Кнопка "Сканировать ценник" → тот же сканер → код ESL.
3. Как только обе пары заполнены, активна кнопка "Отправить в Oracle":
   - строка сразу сохраняется локально (Room, `pending_scans`) —
     на случай обрыва Wi-Fi в торговом зале;
   - идёт `INSERT` в staging-таблицу;
   - затем вызывается процедура выгрузки в ESL_WORK;
   - результат (успех/ошибка) показывается на экране.
4. Экран "Очередь" показывает последние 200 сканирований со статусом
   (`PENDING` / `SENT` / `FAILED`) и кнопкой "Повторить" для несостоявшихся
   отправок — полезно, если магазин временно не в сети.
5. Экран "Настройки": host/port/service name, логин/пароль (хранится в
   `EncryptedSharedPreferences`), код магазина, имя staging-таблицы и
   процедуры. Кнопка "Проверить подключение" делает `SELECT 1 FROM dual`.

## Сборка APK без своего компьютера — через GitHub Actions

В проекте есть `.github/workflows/build.yml` — при пуше в GitHub он сам
соберёт debug APK на серверах GitHub и приложит его как скачиваемый файл
(«artifact»), никакой установки Android Studio не требуется.

1. Создай (если ещё нет) бесплатный аккаунт на github.com.
2. Создай новый репозиторий (Private — ок, для личных аккаунтов Actions
   работает и на приватных репозиториях, есть бесплатный лимит минут).
3. Загрузи туда содержимое папки `EslScanner`:
   - **Без git**: на странице пустого репозитория жми "uploading an existing
     file" и перетащи ВСЮ папку `EslScanner` (её содержимое, не архив) в
     окно браузера — современный GitHub сохраняет структуру подпапок.
   - **С git** (проще для дальнейших правок):
     ```
     cd EslScanner
     git init
     git add .
     git commit -m "initial"
     git branch -M main
     git remote add origin https://github.com/<твой_логин>/<репозиторий>.git
     git push -u origin main
     ```
4. Открой вкладку **Actions** в репозитории — workflow "Build APK" запустится
   автоматически после пуша. Сборка идёт 3-7 минут.
5. Когда сборка позеленеет (✅), зайди в неё и внизу страницы найди раздел
   **Artifacts** → `EslScanner-debug-apk` → скачай zip, внутри — `app-debug.apk`.
6. Дальше — как обычно: скопировать на телефон и установить (разрешить
   "Установка из неизвестных источников" при первом разе).

Каждый следующий `git push` (после правок под реальную схему БД) будет сам
пересобирать новый APK — заходить в Actions и скачивать свежий артефакт.

## Важные оговорки

- **Безопасность**: логин/пароль от Oracle хранятся на телефоне
  (зашифрованно), но при прямом JDBC-подключении с устройства это всё равно
  расширяет поверхность атаки по сравнению с промежуточным REST-сервисом.
  Для боевого прод-контура обычно советуют REST-прослойку с отдельным,
  ограниченным по правам техническим пользователем БД — но раз выбран
  прямой JDBC, у пользователя БД в приложении должны быть права только на
  INSERT в staging-таблицу и EXECUTE на процедуру выгрузки, не более.
- **TLS/версия Oracle**: если сервер БД старый (как в вашем случае с Oracle
  11.2.0.3 для PriSmart-интеграции), обычный JDBC thin без TLS будет работать
  так же, как ваши текущие PL/SQL-подключения — ограничение TLS 1.0 там
  касалось UTL_HTTP, а не клиентских JDBC-подключений к самой базе, так что
  тут проблемы быть не должно.
- **Разные форматы штрих-кодов**: сканер настроен на `FORMAT_ALL_FORMATS`,
  что покрывает и EAN/UPC (товары), и Code128/QR (обычно используются на ESL).
  Ручной ввод кода доступен на обоих экранах сканирования на случай
  повреждённой этикетки.
